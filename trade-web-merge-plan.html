Plan · Site merge

Trade Web + Player Projections

The Trade Web becomes the one site for both projects: trade history, value rankings, the trade machine, and every club's assets, with one player page for value, contract, and stats. The MiLB repo stays as the Python model and stops hosting a site.

approved 2026-11-18 spec: trade-web-merge-spec.md
Every block has an ID. To change one, say S3 should be X, not Y and only that block gets edited. IDs are never reused or renumbered.

Problem

P1

Two sites show overlapping numbers about the same players.Every UI change happens twice, and a player's value lives on one site while his trade history lives on the other.

P2

The Trade Web player page has no stats for most MLB players who were never traded, and there's no view of a club's whole asset base.

Who it's for

U1

Jack, plus anyone he sends the link to (front office contacts, interviewers). Public, desktop first, must work on a phone.

Architecture

In scope

S1

Top tabs become Trade Web, Teams (renamed from Team Flows), Trade Returns, Trade Machine (new), Player Projections (new).

S2

Teams gets an Assets sub-tab next to the two it already had (Trees and Ledger, unchanged). One club selector drives all three.Changed at build: Team Flows already had two sub-tabs, so Assets became the third.

S3

Assets shows two columns for the selected club: MLB (established MLB players, about 35 per club) and Minors (its prospects). Each row: name, position, age, level or contract, value with its 10th-90th range. Highest value first.

S4

Tapping any player anywhere opens the one player page.

S5

Player page shows value (range and value read), contract year by year for MLB players or P(MLB), career WAR, ETA for prospects, and stats: MLB year-by-year on top, MiLB by level below.

S6

Player Projections tab: all 8,002 valued players on one board, filters for name, hitter/pitcher, MLB vs prospect, level, club, low confidence, plus sorting.Changed at build: the MiLB leaderboard file holds only the 6,958 prospects, so the board joins the value file to it.

S7

Trade Machine tab: the MiLB trade simulator moved over as-is (value in vs out, 40-man limit, 2027 payroll vs the tax line, Shop a player), restyled to match.

S8

Methodology page moves into the Trade Web. Links to milb-hitter-value.netlify.app point inside the Trade Web.

S9

Every new view has a shareable URL and works with browser back/forward.

S10

MiLB repo stops publishing a site (site/ pages and netlify.toml removed). Jack shuts down the Netlify site after the Trade Web PR is live.

Approach

A1

The Trade Web is the only site; new views follow its one-file-per-view pattern.It already has routing, history, and the look we want. The MiLB site has neither routing nor history.

A2

A final MiLB pipeline step writes straight into the Trade Web's public/data/; Jack commits there.The model only changes when the pipeline runs, so a daily fetch from a middle site buys nothing.

A3

Minor league stats: one small file per prospect, loaded when his page opens (0.7 KB each). MLB stats for all 1,044 valued MLB players join the existing players.json, which already loads only on demand and refreshes daily.Changed at build: players.json was already lazy, so adding them (5.8 to 6.6 MB) met the goal with no new loader.

A4

Daily GitHub Action keeps trades, player stats and Savant, drops the values fetch. fetch-values.mjs stays as the converter b34 runs, since the daily grader reads values.json.Values now arrive by commit.

A5

Rankings and trade machine code is ported into Trade Web views using its existing money format, helpers, and styles.One look, one money format.

A6

Keep the existing BREF map as the one place club codes translate (SDP vs SD).
